# Telegram-бот для управленческого учёта

Проект на Python для вашего существующего Telegram-бота: журнал поступлений и расходов, точные денежные расчёты, извлечение таблиц из файлов, Excel-выгрузка, графики и ответы ИИ по сохранённым документам. Входная точка — `bot.py`; используйте токен существующего бота.

Это MVP, а не замена 1С или полноценному бухгалтерскому учёту. В нём нет двойной записи, плана счетов, регламентированных налоговых деклараций, банковской интеграции и автоматического определения налогового режима. «Поступления минус расходы» — разница кассовых записей, не бухгалтерская прибыль.

## Быстрый запуск: macOS / Linux

Нужен Python 3.11 или новее. Распакуйте архив, откройте терминал в папке проекта и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` в текстовом редакторе. В `BOT_TOKEN` вставьте токен вашего бота, полученный у `@BotFather`. Токен не нужно присылать в чат или добавлять прямо в Python-код.

`ALLOWED_USER_IDS` содержит разрешённые **числовые Telegram user ID**, не username и не ID бота. Если свой ID неизвестен, оставьте временную заглушку `1`, запустите бот и напишите ему `/whoami` в личном чате. Эта команда показывает только ID отправителя, даже если ему закрыт доступ. Остановите бот, замените `1` на полученный ID и запустите снова. Для нескольких пользователей: `123456789,987654321`.

```bash
python bot.py
```

Для распознавания фото, создания таблиц из свободного текста и вопросов по документам заполните `OPENAI_API_KEY`. Используется ваш собственный API-аккаунт; он может тарифицироваться отдельно от подписки ChatGPT. Ключ можно оставить пустым: таблицы из CSV/XLSX/DOCX, журнал, калькулятор, сумма столбца и Excel будут работать локально.

Модель задаётся через `OPENAI_MODEL`; по умолчанию `gpt-4.1-mini`. Нужна модель, поддерживающая изображения, Chat Completions и Structured Outputs. Проверьте доступность модели в вашем API-аккаунте. При смене `OPENAI_BASE_URL` проверьте совместимость API и условия обработки данных нового провайдера. По умолчанию применяется официальный endpoint OpenAI, а не какой-либо ключ или сервис Manus.

Для поддерживаемой Google Gemini модели можно использовать совместимый OpenAI endpoint, задав в Environment variables: `OPENAI_API_KEY` (Gemini API key), `OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/` и `OPENAI_MODEL=gemini-3.8-flash` (если эта модель доступна вашему аккаунту). Названия моделей и бесплатные лимиты меняются. Google указывает, что содержимое запросов в бесплатном Gemini API может использоваться для улучшения продуктов и проверяться людьми. Не передавайте на бесплатный уровень конфиденциальные бухгалтерские документы, персональные или банковские данные.

Проверьте в Telegram `/start`, затем `/privacy`. Команда `/consent` разрешает последующую внешнюю обработку; без неё документы в ИИ не передаются. `/revoke` прекращает будущие запросы, но не отзывает уже переданные данные.

Для остановки нажмите `Ctrl+C`. Для непрерывной работы процесс должен быть запущен на постоянно включённом компьютере или вашем сервере с менеджером процессов. Этот архив сам ничего не размещает и не запускает в интернете. Для одного токена должен работать только один polling-процесс. Если старый бот уже использует токен, сначала остановите его. Существующий webhook автоматически не удаляется: переключайте способ доставки обновлений осознанно.

### Windows

## Работа с документами

Пришлите файл в личный чат с ботом. Поддерживаются `.pdf`, `.docx`, `.xlsx`, `.csv`, `.txt`, `.json`, `.png`, `.jpg`, `.jpeg`, `.webp`. Старые `.xls` и `.doc` сначала преобразуйте в `.xlsx` и `.docx`. Аудио, видео, архивы и произвольные форматы не поддерживаются.

CSV/XLSX читаются локально без ИИ. Текстовые значения и их ведущие нули сохраняются; числовые форматы XLSX вроде `00000` не воспроизводятся. Формулы Excel не выполняются и не пересчитываются. Для XLSX первая непустая строка используется как заголовки; для CSV — первая строка. Проверьте результат. DOCX читается локально: основной текст и обычные таблицы, без колонтитулов, сносок, текстовых полей и вложенных изображений. PDF с достаточным текстовым слоем и без встроенных изображений читается локально; страницы с малым количеством текста или изображениями растеризуются и передаются в ИИ только при согласии. Даже логотип может вызвать этот режим. Это эвристика: сложный PDF может потребовать отдельного фото/скана нужной страницы. Фото и скан-страницы распознаёт мультимодальная модель, поэтому возможны ошибки.

Свободные данные отправляйте явно командой:

```text
/text Данные для таблицы: дата 2026-10-25, категория Продажи, сумма 1250.50, валюта RUB.
```

Без ИИ текст сохранится для последующей обработки. При включённом ИИ бот постарается построить таблицу. Если документ уже сохранён без таблицы, выполните `/table ID`. Создаётся новый документ: прежний исходник не заменяется. Если таблицы уже есть, `/table` просто отдаёт Excel.

Команды `/docs` и `/use 7` позволяют найти и выбрать документ. `/use all` включает поиск по всем вашим сохранённым документам. После загрузки автоматически выбирается последний файл; выбор хранится в памяти и после перезапуска сбрасывается к последнему документу.

```text
/ask Какие неоплаченные счета видны в выбранных документах?
/ask Какие расходы стоит проверить и почему?
/export 7
/sum 7 1 3
/chart 7 1 1 3
```

Команда `/sum` суммирует третий столбец первой таблицы документа №7 с помощью `Decimal`, не ИИ. Если встретится непустая неоднозначная ячейка, вычисление прекращается с указанием строки. Пустые ячейки подсчитываются отдельно. Валюты и единицы измерения автоматически не распознаются; не складывайте разные валюты. Строка «итого» тоже попадёт в сумму, если она находится в выбранном столбце: уберите такие строки или подготовьте корректную таблицу до расчёта.

Команда `/chart 7 1 1 3` создаёт Excel-файл с горизонтальной диаграммой и исходными строками: документ №7, таблица №1, столбец категорий №1, числовой столбец №3. Нумерация начинается с 1. График ограничен 200 строками, не группирует дубли и не меняет журнал; точные суммы проверяйте через `/sum`. Используйте постоянную клавиатуру меню (команда `/menu`) для загрузки файлов, просмотра документов, экспорта, построения графика, вопроса ИИ, проверки таблицы, отчёта и помощи.

Кнопка «Проверить таблицу» просит ИИ отметить возможные пропуски, дубликаты, неоднозначные форматы и улучшения структуры. Ответы ИИ используют поиск по словам и ограниченную выборку фрагментов, а не весь текст всех файлов. Ответ включает метки вроде `[D7:фрагмент2]` и размер выборки. Для полноты выбирайте конкретный документ и задавайте узкий вопрос. ИИ предлагает, что проверить или отредактировать, но не изменяет исходный файл, базу или журнал. Точные итоги журнала получайте через `/report`, а не из свободного ответа модели. ИИ не исполняет SQL и не вносит записи.

## Журнал и расчёты

Документы и таблицы **не попадают в журнал автоматически**. Вносите проверенные операции явными командами; комментарий после `|` необязателен:

```text
/income 1250.50 RUB 2026-10-25 Продажи | Оплата заказа
/expense 500 RUB 2026-10-25 Аренда | Офис
/report
/report 2026-10-01 2026-10-31
/ledger 2026-10-01 2026-10-31
/void 12
/calc (1200 + 350) * 2
/vat 1200 20
```

Суммы операций — положительные, максимум два знака после десятичного разделителя. Для команд `/income` и `/expense` не вставляйте пробелы в сумму, поскольку пробел разделяет аргументы. Поддерживаются RUB, USD, EUR, KZT, BYN, UAH, GEL, GBP, CNY. Сводка считает валюты раздельно, без конвертации. Период включает обе границы. `/void` аннулирует только вашу запись, сохраняя её в истории; аннулированные записи исключаются из итогов.

Операции хранятся в минимальных денежных единицах; суммы журнала и столбцов не вычисляются через `float`. Одна операция ограничена 12 цифрами до запятой; отдельное число в `/sum` и `/vat` — по модулю до `10^18`. Повторная обработка одного Telegram-сообщения не создаёт дублирующую запись журнала. Новое сообщение с той же суммой — новая операция. `/calc` разрешает только числа, скобки и `+ - * /`; Python-код, функции и степени запрещены. Для деления применяется Decimal с точностью 256 значащих цифр; бесконечные десятичные дроби всё равно округляются. Денежное отображение округляется до двух знаков HALF_UP. `/vat` показывает оба варианта: выделение налога из суммы и начисление сверху. Ставку передаёте вы; пример `20` — число для демонстрации, не рекомендация действующей ставки.

## Базы данных

По умолчанию создаётся `data/accountant.db` в папке проекта. SQLite подходит для небольшого личного учёта. Тексты, таблицы, согласие и операции сохраняются между перезапусками.

Для PostgreSQL создайте отдельную базу и пользователя с правами только на неё, затем измените `.env`:

```dotenv
DATABASE_URL=postgresql+psycopg://bot_user:PASSWORD@localhost:5432/accountant
```

Драйвер `psycopg` уже указан в зависимостях. Специальные символы пароля в URL должны быть закодированы. При подключении к удалённому PostgreSQL настройте проверку TLS и сертификатов под вашу инфраструктуру. Бот создаёт свои таблицы и работает только с ними; изменение `DATABASE_URL` не переносит автоматически данные из SQLite.

Запросы параметризованы, и в каждом чтении/изменении проверяется владелец. У ИИ нет доступа к произвольному SQL. Поддержка БД означает хранение и отчёты по схеме этого приложения, а не подключение к любой чужой бухгалтерской базе. Для существующей базы, 1С, CRM или другого SQL-движка нужен отдельный адаптер по вашей схеме с явно ограниченными правами. Не подключайте этот MVP напрямую к рабочей базе предприятия с административной учётной записью.

## Развёртывание на FadeHost из GitHub

Этот проект работает через Telegram long polling, поэтому ему не нужны публичный веб-адрес, открытый порт, `PORT` или настройка webhook. FadeHost описывает Telegram-боты как поддерживаемые приложения, автоматически обнаруживает Python из `requirements.txt`, умеет устанавливать репозиторий из GitHub и повторно развёртывать его после push.

1. Создайте **private**-репозиторий GitHub и загрузите в корень проекта файлы из этого проекта. В репозитории должны находиться `bot.py`, `requirements.txt`, `config.py`, `storage.py` и остальные Python-модули. Не добавляйте настоящий `.env`, содержимое `data/`, базу `.db` и `.venv`.
2. Войдите в FadeHost, откройте раздел приложений и создайте Telegram bot / application, выбрав **свой GitHub repository** вместо шаблона. Подключите FadeHost GitHub App к вашему аккаунту и разрешите ей доступ только к этому частному репозиторию. Выберите ветку `main`.
3. Оставьте язык Python с auto-detect либо выберите поддерживаемую версию Python 3.12. Зависимости указаны в `requirements.txt`, точка входа — `bot.py`; если панель запросит отдельную команду запуска, укажите `python bot.py`. Отдельную команду сборки для этого проекта задавать не нужно.
4. В панели приложения откройте Environment variables и добавьте по одной переменной:

```text
BOT_TOKEN=токен_от_BotFather
ALLOWED_USER_IDS=числовой_telegram_ID
DATABASE_URL=sqlite:////data/accountant.db
```

Для распознавания фото и вопросов с ИИ добавьте также `OPENAI_API_KEY=ваш_API_ключ`. Он необязателен и может тарифицироваться отдельно. Важно: используйте имя `BOT_TOKEN`, потому что его ожидает код проекта. Не копируйте из стороннего шаблона переменную `TELEGRAM_BOT_TOKEN` — этот код её не читает. Значения введите через форму FadeHost, а не в репозиторий.

`ALLOWED_USER_IDS` — ваш числовой ID Telegram. Если вы ещё его не знаете, сначала задайте `ALLOWED_USER_IDS=1`, разверните сервис и отправьте боту `/whoami`. Затем замените значение на полученный ID в настройках FadeHost. До правильной настройки ID доступ к бухгалтерским командам закрыт.

5. Нажмите Deploy и откройте Live console. Успешный старт выводит `Бот запущен (polling)`. Напишите боту `/start`, затем проверьте `/calc 2 + 3`.

Каждый Git push в выбранную ветку инициирует повторное развёртывание, если FadeHost GitHub App подключён. Дождитесь завершения нового Deploy и проверьте консоль. Ошибочный релиз можно откатить из списка Deploy history.

### Важно: постоянное хранение базы

FadeHost заменяет папку с кодом при Git deploy; постоянные данные приложения нужно хранить в `/data`. Поэтому для этого проекта задайте `DATABASE_URL=sqlite:////data/accountant.db`. `sqlite:////data/...` — корректный формат абсолютного Linux-пути. Файл базы, WAL-файлы и записи тогда находятся в каталоге данных, а не в папке исходников. Проект также автоматически выбирает `/data`, если этот путь существует и доступен для записи, но переменная делает выбор явным.

По опубликованному описанию FadeHost бесплатный план для одного подтверждённого аккаунта даёт 256 МБ RAM, 0.25 vCPU и 3 ГБ диска, а polling работает постоянно без «сна». У этого бота много библиотек для документов и PDF: следите за показателями памяти и за сообщениями о нехватке RAM/перезапусках. При регулярных перезапусках из-за нехватки памяти понадобится больший план. Проверьте актуальные условия в панели перед созданием.

Проверьте доступные условия резервного копирования `/data` и включите подходящий вариант либо отдельно копируйте базу. Без резервной копии потерю данных при удалении приложения, ошибке настройки или проблеме хостинга можно не восстановить. Существующая SQLite-база с вашего компьютера не появится на FadeHost автоматически. GitHub передаёт исходный код, а не локальные документы и журнал. Перенос базы выполняется отдельно; никогда не кладите её в GitHub.

## Ограничения и защита данных

В коде действуют лимиты: файл до 10 МБ, PDF до 20 страниц, не более 10 изображений/скан-страниц на обработку ИИ, текст до 200000 символов, до 10 таблиц, 2000 строк и 50 столбцов в одной таблице, 30000 ячеек суммарно. Для XLSX ограничен и размер листа: до 2001 строки с заголовком и 50 столбцов, включая пустые/форматированные диапазоны. На пользователя можно хранить до 50 документов и 20 МБ извлечённых данных. Для обращения к ИИ допускается до 20000 символов исходного текста; большой текст можно сохранить локально и разделить перед извлечением. При превышении лимитов бот просит разделить файл, а не молча обрезает его. Журнал экспортируется до 10000 записей за выбранный период; для большего объёма выбирайте более узкий период. Размер контекста ИИ намеренно ограничен.

Есть ограничение 30 запросов ИИ в сутки на пользователя **в пределах одного запуска**, а также ограничение параллельных обращений. Счётчик запросов хранится в памяти и сбрасывается при перезапуске: это защита от случайного расхода, не надёжный биллинговый лимит. Установите бюджет и уведомления в API-аккаунте. Автоматические повторные платные обращения отключены; после сетевой ошибки провайдер всё же мог обработать и тарифицировать запрос.

Доступ разрешён только заданным ID и только в личных чатах. Каждая запись привязана к владельцу. Загруженные документы считаются недоверенными: их инструкции не должны менять поведение помощника, а модель не получает инструментов для выполнения кода или SQL. Это уменьшает последствия prompt injection, но не гарантирует истинность ответа. Перед учётом сверяйте суммы, реквизиты, даты и валюты.

Оригиналы файлов удаляются из временной папки после обработки, а извлечённые данные остаются в базе. База этим кодом не шифруется. Защитите диск и резервные копии, не публикуйте `.env`, не передавайте ботом пароли, карточные данные и служебные секреты. Telegram и внешний ИИ — отдельные получатели данных; согласуйте такую обработку с требованиями вашей организации и законодательства.

```text
/privacy
/revoke
/forget 7
/forget_confirm КОД_ИЗ_ОТВЕТА_БОТА
```

Подтверждение удаления действует две минуты. Документ удаляется только из рабочей базы приложения; сообщение в Telegram, резервные копии и ранее переданные провайдеру данные этим не удаляются. Журнал при этом не затрагивается.

Резервную копию SQLite делайте через штатный backup API или после остановки процесса, а не копированием одного `.db` во время записи в WAL-режиме. Для PostgreSQL используйте `pg_dump`. Перед серьёзным применением нужны миграции схемы, управление секретами, мониторинг, резервное копирование с проверкой восстановления и профессиональная проверка требований к бухгалтерскому учёту.

## Проверка кода

```bash
python -m pytest -q
```

Тесты работают на локальных временных фикстурах. Они не подключаются к Telegram или OpenAI и не требуют реальных токенов. Установка зависимостей и офлайн-тесты не доказывают, что ваш токен, модель или сервер БД доступны: после настройки обязательно проведите проверку в Telegram на нечувствительном документе.

`requirements-lock.txt` содержит точные версии библиотек из проверенного окружения. Для воспроизводимой установки можно использовать `python -m pip install -r requirements-lock.txt` вместо диапазонов из `requirements.txt`.

Основные файлы: `bot.py` — команды Telegram; `ingest.py` — чтение форматов; `ai_service.py` — ИИ и выборка источников; `storage.py` — база с разделением владельцев; `accounting.py` — расчёты; `exports.py` — Excel; `domain.py` — схема данных; `config.py` — настройки. Ссылки на документацию приведены в `SOURCES.md`.
